An ssh-agent for keys in the Mac's Secure Enclave.

For unattended work, a coding agent pushing and signing as a bot: the key cannot leave the Mac, and a policy says what it signs.

v0.2.0 · MIT · Apple silicon, macOS 15 or later · Install

# A key made inside the Enclave. It signs with the screen locked; the line printed is what GitHub takes.
$ taciturn key create bot -use locked -peers path=/usr/bin/ssh,path=/usr/bin/ssh-keygen
# GitHub's host keys, to pin. Compare them with the fingerprints GitHub publishes.
$ ssh-keyscan github.com > github.keys 2>/dev/null
# bot may authenticate to github.com as git, and nowhere else.
$ taciturn key allow bot -user git -host github.com -known-hosts github.keys
# ssh and ssh-keygen now ask taciturn.
$ export SSH_AUTH_SOCK="$HOME/Library/Application Support/taciturn/agent.sock"
# Bound to GitHub's host key and checked against the policy before anything is signed.
$ ssh -o IdentityFile=none -T git@github.com
# Every request: which process, which key, which host, allowed or refused.
$ taciturn log -key bot

Why taciturn

The key never leaves the Mac

The Secure Enclave makes the key and keeps it: ECDSA P-256, the one curve it implements, with no export path at all. The key is an item in the data-protection keychain under taciturn's own access group, so a process not signed with that group cannot even see it, and the agent's socket is the only road to it. A disk image, a backup or another Mac gets nothing: the material is wrapped by this Enclave and unwraps nowhere else.

A signature only for what the key may do

Each key carries its own policy: which hosts it may authenticate to, as which user, pinned to the hosts' keys; which ssh-keygen -Y sign namespaces it may sign in; which programs may ask. The agent reads the destination OpenSSH binds to the connection, the user in the authentication request and the namespace in a signature request, and answers only inside the policy. At any other host the key is not offered. A forwarded agent gets nothing, and a client cannot add, remove or lock keys: to its clients the agent is read-only, and the policy is edited from the shell.

# Refused: at a host the policy does not name, no key is even offered.
$ ssh -o IdentityFile=none -T git@gitlab.com
# And commits and tags, in the git namespace.
$ taciturn key sshsig bot -namespace git

Every use recorded

One line per request, allowed or refused: the process that asked, by path and signing identity, the key, the host and user or the namespace, and the rule that decided. A refused client is told nothing but failure; the reason is in the log. Nothing is asked of the Enclave for a request a rule refused, so the log is also the record of what was not signed. taciturn log prints it, -follow tails it, -json passes it through.

How it works

The agent
One binary, taciturn, running as a user LaunchAgent, org.forkcloser.taciturn, on a fixed socket, ~/Library/Application Support/taciturn/agent.sock. taciturn install writes the LaunchAgent and starts it; taciturn status and taciturn doctor report on it. It ships as Taciturn.app, signed with a Developer ID, because the keychain access group needs a signed bundle: a command-line tool that happens to live in one, run by path, never through the Finder.
Keys
Made in the Enclave by taciturn key create, each with a class chosen at creation: locked, which signs while the screen is locked, until the next boot, or unlocked, which signs only while the session is unlocked. The key lives in the keychain, labelled by its fingerprint; what is on disk under ~/Library/Application Support/taciturn/keys is a record of name, class, public key and policy, with no key material.
Policy
Three lists per key. Destinations: a user, a host, and the host's keys copied from a known_hosts file by taciturn key allow; the keys are the truth, since the protocol carries the server's key and never its name. Namespaces: what taciturn key sshsig allowed. Peers: who may ask, as any, a path= glob on the executable, or an Apple code-signing requirement, stated at creation and edited by taciturn key peers. The agent reads the store on every request, so an edit from the shell is live at the next request, with no reload and no second copy of the state.
The log
JSON lines in ~/Library/Logs/org.forkcloser.taciturn/audit.log, the agent's only output: time, connection, peer process, request, key, binding, outcome and rule.
Unattended sessions
A sandboxed session reaches the socket and nothing else: the Enclave is unreachable from inside the sandbox, so a session that could read the key record still could not use it. The session's ssh is pointed at the socket with IdentityAgent, or SSH_AUTH_SOCK, and a locked key keeps signing after the screen locks, which is when unattended work happens. The client must be OpenSSH 8.9 or later, Apple's included: a client that does not bind the connection gets no authentication signature.
Rotation
taciturn key rotate makes a successor in the Enclave with the same class and policy and serves both; taciturn key signers prints the allowed-signers line with its validity window, so commits the old key signed keep verifying and commits it signs after its retirement do not; taciturn key retire stops serving a key, taciturn key delete removes it and reminds you to revoke it on GitHub.

Install

An Apple silicon Mac on macOS 15 or later. Clients: OpenSSH 8.9 or later; the ssh and ssh-keygen macOS ships qualify.

# The one release asset: the bundle and nothing else.
$ curl -LO https://github.com/forkcloser/taciturn/releases/download/v0.2.0/taciturn_0.2.0_darwin_arm64.tar.gz
# The attestation GitHub recorded when the release workflow built it, checked against this repository.
$ gh attestation verify taciturn_0.2.0_darwin_arm64.tar.gz --repo forkcloser/taciturn
# The bundle, in a folder that stays put: the LaunchAgent runs it by its real path.
$ mkdir -p ~/Applications && tar -xzf taciturn_0.2.0_darwin_arm64.tar.gz -C ~/Applications
# The commands on this page assume the binary on your PATH.
$ export PATH="$HOME/Applications/Taciturn.app/Contents/MacOS:$PATH"
# The LaunchAgent, written and started.
$ taciturn install
# The Enclave, the keychain group, the store, the agent and the socket, in one report.
$ taciturn doctor

Download with curl, as above, not a browser: the bundle is signed but not notarized, and a browser download carries the quarantine flag that Gatekeeper acts on. Upgrading is the same steps with the new version, then taciturn install again, since the LaunchAgent names the binary's path.

Without gh

The checksums file is signed keyless by the release workflow and verifies with cosign; then the archive verifies against the file.

$ curl -LO https://github.com/forkcloser/taciturn/releases/download/v0.2.0/checksums.txt
$ curl -LO https://github.com/forkcloser/taciturn/releases/download/v0.2.0/checksums.txt.sigstore.json
$ cosign verify-blob --bundle checksums.txt.sigstore.json --certificate-oidc-issuer https://token.actions.githubusercontent.com --certificate-identity https://github.com/forkcloser/taciturn/.github/workflows/release.yaml@refs/tags/v0.2.0 checksums.txt
$ shasum -a 256 --ignore-missing -c checksums.txt

For aqua users, taciturn is pinned as a github_release package with GitHub artifact attestation; the registry entry is in farcloser/limen-install.
